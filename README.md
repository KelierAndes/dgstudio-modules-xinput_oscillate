# 手柄震动联动（DGStudio 模块）

DGStudio 联动模块：监听以 XInput 协议接入的手柄的**震动信息**，把游戏派发
的震动强度与状态整理成只读变量登记进「事件流」页的变量表；设备动作（郊狼
电刺激、负鼠振动等）一律在「事件流」里用写入卡片按这些变量编排，本模块不
再自带映射表、也不会自己下发任何设备指令。

**不注入游戏**：模块经 ViGEm 创建一只虚拟 Xbox 360 手柄，游戏照常通过
自己的 XInput 通道把震动派发给它，派发结果由虚拟手柄的震动反馈通道回流
到本模块——数据全程走游戏与系统的原生震动派发链路。

依赖：**无必装 pip 依赖**（纯 Python 标准库 + 随模块分发的 ViGEmClient.dll）。
需本机安装 **ViGEmBus 驱动**（一次性，官方
<https://github.com/nefarius/ViGEmBus/releases>；模块启动时自动探测，
缺失时降级并给出日志指引）。

* DGStudio 核心仓库：<https://github.com/KelierAndes/DG-Lab-Studio>
* 模块市场仓库：<https://github.com/KelierAndes/dgstudio-modules-market>

## 功能

无实体手柄时，**键盘键位映射**把键盘输入合成到虚拟手柄（调试通道）；
玩实体手柄时可开启**透传**，把实体手柄输入合并进虚拟手柄——游戏改用
虚拟手柄后震动才能观测到。

模块把观测到的震动整理为以下变量（「事件流」页变量表的系统栏，方向为**读**）：

| 参数 | 说明 |
|---|---|
| `xvib_l` / `xvib_r` | 左/右马达包络强度 0-100 |
| `xvib_max` | 双马达较大值 0-100（写入通道强度用它最直观） |
| `xvib_active` | 震动激活：包络峰值超过「激活阈值」为 1，回落为 0（适合做脉冲/开火的门控条件） |
| `xvib_link` | 震动链路：超时窗口内收到游戏震动派发为 1 |
| `xvib_pad` | 虚拟手柄就绪（游戏可见手柄）为 1 |

## 安装

1. **安装 ViGEmBus 驱动**（仅首次）：从官方 Releases 下载
   `ViGEmBus_1.22.0_x64_x86_arm64.exe` 安装。模块启动时探测，未安装会
   在日志中提示并降级（虚拟手柄不可用，仅测试注入可用）。
2. **安装模块**：DGStudio 模块页 → 安装并启动。本模块**只登记变量**，
   不会自己下发任何设备动作——不连事件流就不会有设备被驱动。

## 配置与使用

### 模块设置

| 设置 | 默认 | 说明 |
|---|---|---|
| 创建虚拟手柄 | 开 | 经 ViGEmBus 建虚拟手柄接收游戏震动派发 |
| 键盘映射 | 开 | 键位表把键盘输入合成到虚拟手柄（无手柄调试） |
| 实体手柄透传 | 关 | 实体手柄输入合并进虚拟手柄（游戏改用虚拟手柄后震动可观测） |
| 键盘键位表 | 见下 | 槽位 → 键名：a/b/x/y、lb/rb、lt/rt、back/start、ls_click/rs_click、dpad_*、ls_*/rs_*（摇杆与扳机） |
| 强度增益 | 1.0 | 震动百分比放大倍数（结果仍钳制 0-100） |
| 死区 | 2% | 低于该百分比的震动视为 0（过滤游戏微颤） |
| 激活阈值 | 15% | 包络峰值超过该值时 `{xvib_active}` 为 1 |
| 回落时间 | 300ms | 震动归零后包络线性衰减到 0 的时长（设备强度不跳变） |
| 链路超时 | 1000ms | 超时未收到游戏震动派发即视为链路断开 |

默认键位：A=Space、B=Q、X=E、Y=R、LB=1、RB=2、LT=3、RT=4、
Start=Enter、Back=Backspace、左摇杆=WASD、右摇杆=IJKL、十字键=方向键、
L3=C、R3=V。键名支持字母/数字、`Space`/`Enter`/`F1` 等常用名与 `0x` 十六进制。

### 在「事件流」里驱动设备

本模块只把震动读数登记成变量，设备动作全部在「事件流」页的画布上
连线完成（模块内不再有映射表，旧设置里的「输入映射表」会在模块加载时自动
清除并写一条日志）。常用连法：

1. 按住右侧**变量表**行左侧的拖动柄，把 `xvib_max` 等读数**拖到画布**，直接生成
   该变量的**读数卡**（即时输出数值）——已没有「变量对象」这一层；
2. 读数卡输出线需要换算时，接「**范围映射**」「**钳制**」「**公式 / 自由公式**」
   「**比较**」等运算卡；
3. 末端连**核心写入卡**（卡片面板「核心变量」分类下的强度 / 波形 / 开火 /
   脉冲流等）落地到设备——下表把过去用映射表实现的几种效果改写为现在的事件流接线：

   | 核心写入卡 | 事件流接线 | 效果 |
   |---|---|---|
   | 负鼠通道 A 强度 | `xvib_max` 读数卡 → 写入卡 | 手柄怎么震，负鼠就怎么震 |
   | 郊狼通道 A 强度 | `xvib_max` 读数卡 → 范围映射（0-100 → 0-{上限}）→ 写入卡 | 按郊狼当前强度上限折算 |
   | 负鼠通道 A 瞬时脉冲 | `xvib_active` 读数卡 → 写入卡 | 震动超过阈值来一下 1 秒脉冲 |
   | 郊狼开火 | `xvib_active` 读数卡 → 门控 / If-Else 分支 → 写入卡 | 持续大震动期间持续开火 |

4. 执行流入口用「**周期更新**」（如每 100ms 一次）或「**值变动时**」（监控变量
   一变即触发）；急停同样走「急停（全部设备）」写入卡，事件流按 50 ms 节拍
   常驻运行，无需手动播放。

**游玩与自测**：

1. **游玩**：启动游戏，在手柄设置里选择虚拟手柄（无实体手柄时它通常
   就是唯一手柄）；游戏内触发震动即可联动。无手柄调试直接用键盘键位玩。
2. **自测**：控制页绑定负鼠按键到本模块的两个动作——
   「手柄震动测试脉冲…」（向链路注入合成震动，验证事件流连线与设备）；
   「虚拟手柄回环测试…」（对虚拟手柄按 XInput 原生通道派发真实震动，
   验证完整反馈链路）。

## 常见问题

### 安全提示

* 先把全局「最大强度上限」调低再试事件流连线，确认行为后再放开；
* 驾驶/射击类游戏存在持续微震动（路面、后坐力），死区与激活阈值
  配合事件流里的门控 / 分支可避免设备被长期小幅驱动；
* 建议在控制页保留一个「急停」绑定的物理按键（也可在事件流里接
  「急停（全部设备）」写入卡）；
* 游戏被关闭/崩溃时链路超时会让包络自动归零；请勿把 `{xvib_link}`
  接到持续输出类的写入卡上。

### 已知边界

* 虚拟手柄与实体手柄同时存在时，游戏可能优先使用实体手柄的 XInput
  序号——此时请开启「实体手柄透传」，或用 HidHide 等手段对游戏屏蔽
  实体手柄，确保震动派发落到虚拟手柄上；
* ViGEmBus 驱动已停止维护（作者归档），Windows 11 24H2 及以后的新系统
  可能无法全新安装；已装驱动（含本机）不受影响。后续可关注作者的
  替代驱动项目；
* 只覆盖走 XInput 的游戏；DirectInput 或原生 DualShock 路径不经
  XInput，观测不到。
